Repository Structure
====================

The HSK-MensaBot software is organized as a standard ROS 2 workspace. The repository separates the robot software into multiple ROS 2 packages, each providing a dedicated part of the overall system functionality. This modular organization simplifies development, testing and maintenance while allowing individual components to be developed independently.

Main Directories
----------------

The repository contains the following main directories:

* ``src/`` – Contains all ROS 2 packages of the project.
* ``docs/`` – Project documentation generated using Sphinx and Doxygen.
* ``arduino_code/`` – Arduino firmware used for the motor controller.
* ``scripts/`` – Utility and helper scripts used during development.
* ``images/`` – Images and figures used throughout the documentation.
* ``build/`` – Build artifacts generated by ``colcon``.
* ``install/`` – Installed workspace generated after compilation.
* ``log/`` – Build and runtime log files.

ROS 2 Packages
--------------

The ``src`` directory contains the following ROS 2 packages:

* ``imu_ros2_device`` – IMU driver package.
* ``laser_scan_merger`` – Merges multiple LiDAR scans into a single scan.
* ``mensabot_bringup`` – Launch files and system configuration.
* ``mensabot_description`` – Robot description including the URDF model.
* ``mensabot_hardware`` – ros2_control hardware interface.
* ``mensabot_navigation`` – Navigation stack configuration and launch files.
* ``mensabot_simulation`` – Gazebo simulation environment.
* ``mensabot_utils`` – Utility, monitoring and safety nodes.
* ``rf2o_laser_odometry`` – Laser-based odometry package.
* ``sick_safetyscanners2`` – ROS 2 driver for the SICK safety laser scanners.
* ``sick_safetyscanners2_interfaces`` – Custom interfaces for the SICK driver.
* ``sick_safetyscanners_base`` – Base library used by the SICK scanner packages.

Configuration Files
-------------------

The project uses several YAML configuration files to configure sensors, controllers, localization and navigation components.

+-----------------------------------------------+-----------------------------------------------------------+---------------------------------------------------------------+
| Configuration File                            | Location                                                  | Purpose                                                       |
+===============================================+===========================================================+===============================================================+
| ``imu_filter_param.yaml``                     | ``imu_ros2_device/config/``                               | Configuration of the IMU filter.                              |
+-----------------------------------------------+-----------------------------------------------------------+---------------------------------------------------------------+
| ``laser_merger_param.yaml``                   | ``laser_scan_merger/config/``                             | Configuration of the laser scan merger node.                  |
+-----------------------------------------------+-----------------------------------------------------------+---------------------------------------------------------------+
| ``controller.yaml``                           | ``mensabot_bringup/config/``                              | Configuration of the ``diff_drive_controller``.               |
+-----------------------------------------------+-----------------------------------------------------------+---------------------------------------------------------------+
| ``ekf.yaml``                                  | ``mensabot_bringup/config/``                              | Configuration of the Extended Kalman Filter (EKF).            |
+-----------------------------------------------+-----------------------------------------------------------+---------------------------------------------------------------+
| ``amcl_localization.yaml``                    | ``mensabot_navigation/config/``                           | Parameters for AMCL localization.                             |
+-----------------------------------------------+-----------------------------------------------------------+---------------------------------------------------------------+
| ``navigation.yaml``                           | ``mensabot_navigation/config/``                           | Configuration of the Nav2 navigation stack.                   |
+-----------------------------------------------+-----------------------------------------------------------+---------------------------------------------------------------+
| ``slam_toolbox_localization.yaml``            | ``mensabot_navigation/config/``                           | SLAM Toolbox configuration for localization mode.             |
+-----------------------------------------------+-----------------------------------------------------------+---------------------------------------------------------------+
| ``slam_toolbox_mapping.yaml``                 | ``mensabot_navigation/config/``                           | SLAM Toolbox configuration for mapping mode.                  |
+-----------------------------------------------+-----------------------------------------------------------+---------------------------------------------------------------+
| ``gz_bridge.yaml``                            | ``mensabot_simulation/config/``                           | Gazebo ROS bridge configuration for simulation.               |
+-----------------------------------------------+-----------------------------------------------------------+---------------------------------------------------------------+

Repository Organization
-----------------------

The repository follows a modular design in which each ROS 2 package is responsible for a specific subsystem such as robot description, hardware communication, navigation, simulation or utility functionality. Configuration files are grouped inside the corresponding packages, while documentation and development resources are stored separately from the software implementation.

This organization enables individual packages to be developed, tested and maintained independently while keeping the overall workspace structure consistent and easy to navigate.
